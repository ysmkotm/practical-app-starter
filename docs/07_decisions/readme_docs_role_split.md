# READMEとdocs配下ドキュメントの役割分担

**Document Version** : 1.0

**更新日** : 2026/07/30

**ステータス** : 決定

---

## 1. 目的

READMEとdocs配下ドキュメントの間で内容が重複し、どちらが正本か分かりにくくなることを防ぐ。

---

## 2. 背景

READMEには「開発ドキュメント」章（各docsカテゴリの説明）や、「今後の予定」の詳細な機能一覧があり、`docs/README.md`や`docs/01_project/project.md`と内容が重複していた。
どちらかを更新すると他方が古くなるリスクがあり、SSOTの観点で見直しが必要になった。

---

## 3. 検討した案

|案|概要|メリット|デメリット|
|---|---|---|---|
|A. READMEに詳細も残す|開発ドキュメントの代表例や今後の予定を詳しく書く|README単体で把握できる|`docs/README.md`・`project.md`と二重管理になる|
|B. READMEは概要・索引に限定|詳細はdocs配下へ委ね、READMEからリンクする|正本が一つになり、更新漏れが減る|README単体では詳細が分からない|

---

## 4. 判断基準

- 同じ情報を複数箇所に書かないこと（SSOT）
- READMEは初見の人が全体像とdocsへの入口を把握できれば十分であること
- 詳細な一覧・計画は、変更頻度の高いdocs配下で管理する方が実態に合うこと

---

## 5. 判断結果

**案Bを採用**する。

- README「概要」節から`docs/README.md`へリンクし、「開発ドキュメント」章は設けない
- 「今後の予定」は代表的な項目のみ残し、詳細は`docs/01_project/project.md`へリンクする

---

## 6. 判断理由

- READMEとdocsの両方に同じ粒度の情報を持たせると、更新の度に両方を直す必要があり、実運用では漏れが発生しやすい
- READMEは「最初に読む入口」としての役割に絞った方が、SSOTの原則と一致する
- 詳細を先に決めてから概要を書くと、粒度の統一が取りやすい

---

## 7. 今後の対応

- README編集時は、まず「これはdocs配下の正本を更新すべき内容か」を確認する
- docs配下の内容を変更した場合、README側の代表例・リンクが古くなっていないか併せて確認する
