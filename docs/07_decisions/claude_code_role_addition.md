# Claude Codeの役割追加（相談・レビュー・記録係）

**Document Version** : 1.0

**更新日** : 2026/07/30

**ステータス** : 決定

---

## 1. 目的

Claude Code を新たに AI 体制へ加えるにあたり、どの役割から始めるかを決定し、その理由を残す。

---

## 2. 背景

もともと Web の Claude で副業（本書籍プロジェクト）の相談をしていたが、ローカルの成果物を確認しながら相談できたほうがよいと考え、Claude Code へ段階的に移行することにした。

`docs/02_rules/ai.md` §2 では、人間・ChatGPT・Cursor の3者で役割分担しており、Cursor が実装・記録係、ChatGPT が設計相談・レビューを担っていた。Claude Code はこれらと重複する部分・異なる部分があり、役割の切り分けが必要になった。

---

## 3. 検討した案

|案|概要|メリット|デメリット|
|---|---|---|---|
|A. 相談・レビューのみ|実装・記録係は Cursor に残し、Claude Code は相談・レビュー専用とする|既存の実装・記録フローを崩さない|Claude Code の実装能力を活かせない|
|B. 実装・記録係も含め全面移行|Cursor の役割を Claude Code に置き換える|役割が一本化できる|段階2（表現レビュー中）の運用が大きく変わり、移行リスクが高い|
|C. 相談・レビュー＋記録係のみ先行して任せる|実装は当面 Cursor に残し、記録係は運用ルールがツール非依存（`recording.md`）なので同時に任せる|相談・レビューという主用途と、記録（判断・知見の言語化）は親和性が高く両立しやすい。実装の主担当は変えずに済む|記録トリガーの発火タイミングや価値判定がツールごとに完全には揃わない可能性がある|

---

## 4. 判断基準

- 「少しずつ移行する」という当初方針に沿い、一度に大きく変えない
- 実装・記録の主担当を明確にし、混乱を避ける
- `recording.md` がツール非依存の SSOT であるため、記録係の追加は実装ほど移行コストが高くない

---

## 5. 判断結果

**案Cを採用**する。

具体的には以下を実施した。

- `docs/02_rules/ai.md` §2.4 に Claude Code の役割（相談・レビュー、記録係）を追加
- `CLAUDE.md` を新設し、`docs` への入口と記録係の行動トリガーを定義（`.cursor/rules/project.mdc` / `recording.mdc` と同じ構成）
- `docs/02_rules/recording.md` §6・§7 を、Cursor 専用の記載から Claude Code も含む記載に更新

---

## 6. 判断理由

- 相談・レビューは「ローカルの成果物を見ながら対話したい」という当初の動機と直結する
- 実装は Cursor の記録・`progress.md` 更新フローに密結合しており、いきなり主担当を切り替えると運用が崩れるリスクがある
- 記録係は `recording.md` の分類・保存先・価値基準がツール非依存で既に一本化されているため、Claude Code が加わっても実務上の影響は小さい。記録トリガーの発火基準のみ、`CLAUDE.md` 側で「相談・レビューの区切り」に合わせて文言を調整した（`.cursor/rules/recording.mdc` は「実装支援に加え」が前提の書き方だったため、そのまま流用しなかった）

---

## 7. 今後の対応

- 運用して手応えが良ければ、実装や `ai.md` §4.4（チャット運用）、`docs/README.md` §4 の表なども含めて役割を拡大する
- 記録係の判断基準（★評価・粒度）がツール間でずれていないか、実際の記録提案を通じて確認する
