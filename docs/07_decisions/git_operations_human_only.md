# Git操作（ステージング・コミット・プッシュ）の実行主体を人間に限定する明確化

**Document Version** : 1.0

**更新日** : 2026/07/30

**ステータス** : 決定

---

## 1. 目的

Git操作のうち、ステージング・コミット・プッシュ（およびコミットを作成・変更する操作）を誰が実行するかを明確にし、AI協調開発における役割分担の曖昧さを解消する。

---

## 2. 背景

既存の [`docs/02_rules/git.md`](../02_rules/git.md) §1・§7には「コミット前に必ず人間が差分を確認する」という方針があったが、確認の主体（人間）は明確な一方、コミットを実行する主体は明示されていなかった。

実際に、作業中メモ機構の導入を検討・撤回する一連の作業の中で、Cursorが `git revert` を人間の事前の明示的な許可なく実行し、打ち消しコミットを作成する場面があった。差分の説明は行っていたが、実行前に「実行してよいか」の確認は取っていなかった。この事例により、既存の記載だけでは「確認」と「実行」の主体の区別が十分に機能していないことが分かった。

---

## 3. 検討した案

|案|概要|メリット|デメリット|
|---|---|---|---|
|A. 現状維持|「人間が確認してからコミットする」という記載のままとする|変更コストがない|「確認」と「実行」の主体が曖昧なままで、同種の事例が再発しうる|
|B. ステージング・コミット・プッシュの実行主体を人間に限定し、明記する|AIは差分説明・コミットメッセージ案の提示までとし、実行は人間が行うと明記する|「採用判断は人間が行う」という既存方針（`docs/02_rules/ai.md` §3）と一貫する。実行の境界が明確になる|AIに依頼できる範囲が狭まり、実行を都度人間が行う手間が増える|
|C. `revert` など個別コマンドが出るたびに都度口頭で確認する運用とし、ルール化はしない|運用の柔軟性を保つ|記載を変更する必要がない|口頭確認に依存し、同種の事例の再発を防げない|

---

## 4. 判断基準

- 「AI生成物の採用判断は人間が行う」という既存方針（[`docs/02_rules/ai.md`](../02_rules/ai.md) §3）と一貫すること
- 参照系操作（`git status`・`git diff`・`git log` 等）まで制限せず、過剰な制約にしないこと
- 実際に発生した事例（`git revert` の無許可実行）を再発させない実効性があること

---

## 5. 判断結果

**案Bを採用**する。

- ステージング・コミット・プッシュ、およびコミットを作成・変更する操作（`revert`・`reset`・`merge`・`cherry-pick` 等）は、人間が実行する
- AIは、変更内容の説明・差分の提示・コミットメッセージ案の提示までを担当し、上記操作自体は実行しない
- 参照系操作（`git status`・`git diff`・`git log` 等）は対象外とし、AIが必要に応じて実行してよい
- [`docs/02_rules/git.md`](../02_rules/git.md) §1・§7に反映済み

---

## 6. 判断理由

- `docs/02_rules/ai.md` §3は「AIの出力結果は、そのまま正しいものとして扱わず、必ず人間が採用判断を行う」としている。コミットは変更を履歴として採用する行為そのものであり、実行を人間に限定することでこの方針をより確実に徹底できる
- 実際に発生した `git revert` の無許可実行という具体的な事例があり、既存の記載（確認の主体のみ明示）では再発を防げないことが分かった
- 参照系操作まで対象にすると、AIによる状況確認や差分説明ができなくなり実務上の支障が大きい。書き込み系操作に限定することで、過剰な制約を避けつつ実効性を確保できる

---

## 7. 今後の対応

- ブランチ作成・タグ付けなど、今回対象にしなかった他の書き込み系Git操作についても、必要性が生じた場合は同様の観点で見直す
- 実際の運用を通して、AIが実行範囲を守れているかを確認する
- ファイル変更完了時のコミット準備案の提示義務化は、[`commit_prep_proposal_on_ai_file_change.md`](commit_prep_proposal_on_ai_file_change.md) で決定済み（実行主体の限定は本判断のまま維持）
