# 公開ライセンスの選定（Apache-2.0 / MIT）

**Document Version** : 1.0

**更新日** : 2026/07/30

**ステータス** : 決定（Apache License 2.0。BLG-PRJ-007）

---

## 1. 目的

Version 1.0 公開にあたり、リポジトリ（主にアプリケーションソース）に適用する OSS ライセンスを選定する。

選定結果は README・ルートの `LICENSE` に反映する（実装反映は [`PRG-PRJ-002`](../01_project/progress.md)）。

---

## 2. 背景

- 公開・提供方針は確定済み（[`public_offering_strategy.md`](public_offering_strategy.md)）。コードは OSS、強いコピーレフトや Source Available のみには閉じない。
- 収益はリポ直販ではなく、Version 3.x 以降の隣接課金（教材・伴走）を候補とする。ライセンスはこれを妨げないことが前提。
- 候補は実務で一般的なパーミッシブ系のうち、方針文書で明示された **Apache License 2.0** と **MIT License** に絞る。
- GPL / AGPL 等の強いコピーレフト、および Source Available は上流方針により対象外。

---

## 3. 検討した案

### 3.1 候補外（再確認）

|案|扱い|理由|
|---|---|---|
|GPL / AGPL 等|対象外|強いコピーレフト。企業利用・実務流用のハードルが上がる|
|Source Available|対象外|OSS としての受けが弱く、方針で除外済み|
|デュアルライセンス|V1.0 対象外|個人規模では過剰（方針 §5.2）|

### 3.2 Apache-2.0 と MIT の比較

両者とも **パーミッシブ**（商用利用・改変・クローズド派生物可、ソース公開義務なし）。隣接課金（教材・伴走）とも両立する。

|観点|Apache License 2.0|MIT License|
|---|---|---|
|長さ・読みやすさ|長め。条文が明確|短い。初学者にも把握しやすい|
|著作権・再配布|許可。著作権表示・ライセンス文の付与が必要|同左（より簡潔）|
|特許|**明示的な特許許諾**あり。訴訟時の特許ライセンス終了条項あり|特許について明示なし（解釈・地域に依存しやすい）|
|商標|**商標権は許諾しない**と明示|商標について明示なし|
|変更の明示|改変ファイルへの変更表記など、再配布時の条件がやや多い|条件は最小限|
|NOTICE ファイル|プロジェクトに NOTICE がある場合、派生物でも内容の引き継ぎが必要|該当なし|
|エコシステムとの相性|**Spring Boot / Spring 本体が Apache-2.0**。Java 業務系で馴染みやすい|JS／小規模ライブラリで特に多い。スターターでも一般的|
|企業・法務からの見え方|特許条項があり「実務向け OSS」として説明しやすい|シンプルで採用障壁は低い。特許面の説明は弱い|
|隣接収益への影響|リポ外の教材・伴走は妨げない|同左|
|GPLv2 との両立|単独では GPLv2 と非互換とされることが多い（本プロジェクトでは実質問題になりにくい）|GPLv2 との組み合わせは相対的に容易（本プロジェクトでは実質問題になりにくい）|

### 3.3 本プロジェクト固有の当てはめ

|判断材料|含意|
|---|---|
|Spring Boot ベースの業務スターター／リファレンス|スタックと同じ Apache-2.0 は説明コストが低い|
|正式名称「Practical App Starter — Spring Boot Edition」|ブランド名の保護を意識するなら、商標非許諾が明示される Apache-2.0 が有利|
|差別化はコードより docs／AI 協調の進め方|コードライセンスは「使いやすい OSS」で足りる。過保護も過簡略も不要|
|収益は隣接課金（教材原資は knowledge 非公開）|コピーレフト不要。パーミッシブで十分|
|対象者に初学者を含む|MIT の短さはメリット。ただし README で「Apache-2.0＝Spring と同じ系統」と一言あれば十分補える|
|個人開発・当面の特許訴訟リスクは低い|MIT でも実務上大きな差は出にくい。差は主に「明示の安心感」と「エコシステム整合」|

## 4. 判断基準

[`public_offering_strategy.md`](public_offering_strategy.md) §4 および本選定向けに、次を重視する。

1. パーミッシブであること（上流方針）
2. 実務・企業利用の説明しやすさ（ポートフォリオ／リファレンス）
3. Spring エコシステムとの整合
4. 正式名称・ブランドを意図せず許諾しすぎないこと
5. 一人運用で扱える単純さ（デュアルライセンス等は避ける）
6. 隣接課金オプションを閉じないこと

---

## 5. 判断結果

**案 A（Apache License 2.0）を採用する。**

- 適用対象：リポジトリのアプリケーションソースを中心とする公開コード
- 条文反映：ルートの `LICENSE` および README（[`PRG-PRJ-002`](../01_project/progress.md)）
- 不採用：MIT License（案 B）

---

## 6. 判断理由

- Spring Boot と同ライセンスであり、スタックとの説明が一貫する
- 特許許諾と商標非許諾が明示され、実務向けリファレンス／ポートフォリオとして説明しやすい
- パーミッシブのままなので、クローズド派生物や隣接教材課金（Version 3.x 候補）を妨げない
- MIT の短さはメリットだが、本プロジェクトでは README で補える範囲であり、上記の整合・明示性を優先した
