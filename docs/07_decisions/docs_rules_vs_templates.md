# 設計ルールとテンプレートの役割分担

**Document Version** : 1.0

**更新日** : 2026/07/30

**ステータス** : 決定

---

## 1. 目的

開発ドキュメントにおける「設計ルール」と「設計書テンプレート」の役割を明確にし、同じ内容の二重管理を避ける。

---

## 2. 背景

テーブル定義書のデータ型記載（DDL表記をそのまま書く方針）を検討した際、最初は `docs/02_rules/db.md` へルール追加を検討した。

その後、「複数の設計書・DDL・実装に共通する方針」と「その設計書を書くときの書き方・記載例」は分けるべきではないか、という論点が出た。

テンプレート作成を進める中でも、ルールと記載方法が混ざると分かりにくい、という実感があった。

---

## 3. 検討した案

|案|概要|メリット|デメリット|
|---|---|---|---|
|A. 設計に関する内容はすべて `02_rules` に書く|データ型の書き方も含めルール化する|探しやすい場所が一つになる|テンプレート固有の書き方までルールが肥大化する|
|B. 書き方・記載例はテンプレート、設計の考え方はルール|役割を分ける|二重管理を減らせる。使う場所の近くに記載例がある|境界判断が必要になる|
|C. すべてテンプレートに寄せる|ルールファイルを増やさない|設計書作成時に完結する|共通方針が散らばり、プロジェクト全体の一貫性が落ちる|

---

## 4. 判断基準

- 同じ情報を複数箇所へ書かないこと
- 人間と AI の双方が、参照先を迷いにくいこと
- 「どう設計するか」と「どう書くか」を混同しないこと
- 既存の `documentation.md` / `development.md` の方針と整合すること

---

## 5. 判断結果

**案Bを採用**する。

役割分担は次のとおりとする。

|役割|内容|主な置き場所|
|---|---|---|
|共通記法|Markdownの書き方|`docs/02_rules/documentation.md`|
|設計ルール|どう設計するか|`docs/02_rules` 配下の設計に関するルール（例：`db.md`、`naming.md`）|
|テンプレート|どう書くか（構成・記載方法・記載例）|各設計書テンプレート|

役割分担の目安：

- すべての開発ドキュメントに共通する Markdown の書き方 → `documentation.md`
- 複数の設計書・DDL・実装に共通する方針 → 設計ルール
- その設計書を書くときに必要な書き方・記載例 → テンプレート

具体例として、テーブル定義書のデータ型は `db.md` ではなく、テーブル定義書テンプレートのカラム定義付近に記載方法として置く。

---

## 6. 判断理由

- データ型の「`VARCHAR(100)` のように DDL 表記で書く」は、設計思想というより記載方法に近い
- ルールに置くと重く見え、テンプレートに置くと使う場所の近くで参照できる
- `documentation.md` に共通記法、テンプレートに固有の書き方、という既存方針の延長で自然
- 案Aはルール肥大化、案Cは共通方針の散在が起きやすい

---

## 7. 今後の対応

- 迷った場合は [`docs/02_rules/documentation.md`](../02_rules/documentation.md) §9 の役割分担の目安を参照する
- 新しい記載方法を追加するときは、まず「ルールかテンプレートか」を確認する
- 境界が曖昧なものは、必要に応じて本判断記録を見直す
