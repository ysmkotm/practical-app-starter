# EMP002 社員登録・編集

**Document Version** : 1.0

**更新日** : 2026/07/30

## 1. 基本情報

|項目|内容|
|----|----|
|画面ID|EMP002|
|画面名|社員登録・編集|
|画面種類|登録・編集|
|概要|社員情報を新規登録する、または既存社員情報を編集・論理削除する画面です。登録モードと編集モードで同一テンプレートを共用します。|
|権限|未定|

---

## 2. 画面の目的

- 社員情報を新規登録する
- 社員情報を編集・更新する
- 社員を論理削除する

---

### 一意性チェックと DB 制約

社員番号・メールアドレスの一意性は、次の二層で担保する。

|レイヤー|内容|参照|
|---|---|---|
|DB 制約|社員番号（`employee_code`）・メールアドレス（`email`）に UNIQUE 制約を設定する|[`docs/04_db/table/employee.md`](../04_db/table/employee.md) §4|
|アプリ（本画面）|登録・更新時に、自身以外の未削除レコード（`deleted_flg = false`）と重複しないことを事前チェックする|§8.5|

DB 制約は論理削除済みレコードも含むため、アプリの事前チェックを通過しても DB 制約違反が発生しうる。競合時の画面表示は [`BLG-CMN-001`](../01_project/backlog.md) の方針確定後に実装する。

論理削除済みの社員番号・メールアドレスは再利用できない（UNIQUE 制約が論理削除済み行も含むため）。

登録と更新で異なるバリデーションが必要になった場合は、Validation Groups の利用を検討する（[`BLG-EMP-006`](../01_project/backlog.md) 参照）。

## 8. 実装情報

### 8.1 エントリポイント

#### 登録画面表示

|項目|内容|
|----|----|
|URL|`/employee/new`|
|HTTPメソッド|GET|
|テンプレート|[`src/main/resources/templates/employee/form.html`](../../src/main/resources/templates/employee/form.html)|
|Controller|`EmployeeController#showCreate`|

- モデルに `mode` として `"create"` を設定する。
- 空の `EmployeeForm` をモデルに設定する。
- 部署・在籍区分のプルダウン選択肢をモデルに設定する。

#### 編集画面表示

|項目|内容|
|----|----|
|URL|`/employee/{employeeId}/edit`|
|HTTPメソッド|GET|
|テンプレート|[`src/main/resources/templates/employee/form.html`](../../src/main/resources/templates/employee/form.html)|
|Controller|`EmployeeController#showEdit`|

- `{employeeId}` には社員マスタ.社員ID（`employee_id`）を指定する。
- モデルに `mode` として `"edit"` を設定する。
- 対象社員の情報を `EmployeeForm` に設定してモデルへ渡す。
- 対象社員が存在しない、または論理削除済みの場合の扱いは [`BLG-EMP-004`](../01_project/backlog.md) 参照。

#### 登録

|項目|内容|
|----|----|
|URL|`/employee`|
|HTTPメソッド|POST|
|Controller|`EmployeeController#create`|

- `EmployeeForm` で入力値を受け取る。
- バリデーションエラー時は登録画面（登録モード）を再表示する。

#### 更新

|項目|内容|
|----|----|
|URL|`/employee/{employeeId}`|
|HTTPメソッド|POST|
|Controller|`EmployeeController#update`|

- `{employeeId}` には社員マスタ.社員ID（`employee_id`）を指定する。
- 更新対象のキーは **`@PathVariable` の `employeeId` を正** とする。hidden の `employeeId` は設けない。
- `EmployeeForm` で入力値を受け取る。編集モードでは社員番号は画面から送信されない（`th:field` を使わず `name` 属性を付けない。`readonly` 表示のみ）。
- バリデーションエラー時は編集画面（編集モード）を再表示する。再表示時の `employeeId` は `@PathVariable` からモデルへ設定する。

#### 削除

|項目|内容|
|----|----|
|URL|`/employee/{employeeId}/delete`|
|HTTPメソッド|POST|
|Controller|`EmployeeController#delete`|

- `{employeeId}` には社員マスタ.社員ID（`employee_id`）を指定する。
- 削除対象のキーは **`@PathVariable` の `employeeId` を正** とする。hidden の `employeeId` は設けない。
- 論理削除として、社員マスタ.削除フラグ（`deleted_flg`）を `true` に更新する。
- 削除前に確認ダイアログを表示する。メッセージ形式は §8.5 を参照。

### 8.5 データ取得・更新

- 編集画面表示時は、`employee_id` で社員マスタを取得する。`deleted_flg = false` のレコードのみ対象とする。
- 部署プルダウンの選択肢は、部署マスタから `deleted_flg = false` のレコードを `display_order` 昇順、`department_code` 昇順で取得する。編集時に現在の部署が論理削除済みの場合のみ、名称に「（削除済み）」を付与して選択肢へ補完する。
- 在籍区分プルダウンの選択肢は、共通コードマスタから `code_type = 'EMPLOYEE_STATUS'` かつ `deleted_flg = false` のレコードを `display_order` 昇順、`code` 昇順で取得する。編集時の削除済み現在値の補完は部署と同様。
- 登録・更新時は、部署・在籍区分の参照妥当性をサーバー側で検証する（登録は未削除のみ。更新は現在値維持可。詳細は [`emp002_soft_deleted_master_reference.md`](../07_decisions/emp002_soft_deleted_master_reference.md)）。
- 登録時は `employee_id` を自動採番し、`deleted_flg` は `false` を設定する。
- 更新時は `@PathVariable` の `employee_id` をキーに社員マスタを更新する。社員番号は更新しない（編集モードでは読み取り専用）。`updated_at` は更新する。
- 削除時は `@PathVariable` の `employee_id` をキーに `deleted_flg` を `true` に更新する。`updated_at` は更新する。
- 社員番号・メールアドレスの一意性チェックは、登録時・更新時ともに自身以外の未削除レコードと照合する。DB 制約との関係は §6「一意性チェックと DB 制約」を参照する。
- 削除確認ダイアログのメッセージは、対象社員が分かる形式とする。例：`EMP000001：山田 太郎 さんを削除します。よろしいですか？`（社員番号・氏名は編集画面表示時の値を使用する）。

### 8.6 画面レイアウト（登録・編集）

[`docs/02_rules/ui.md`](../02_rules/ui.md) §4（入力画面・整備予定）の初適用例です。共通方針が確定するまでは、本節を EMP002 のレイアウト正とします。

|項目|内容|
|----|----|
|テンプレート|[`src/main/resources/templates/employee/form.html`](../../src/main/resources/templates/employee/form.html)|
|画面固有 JS|[`src/main/resources/static/js/employee/form.js`](../../src/main/resources/static/js/employee/form.js)|
|共通 CSS|[`src/main/resources/static/css/common.css`](../../src/main/resources/static/css/common.css)（`employee-page-header`、`employee-form-card`、`form-label-fixed`、`form-actions`、`btn-form-action` 等）|

#### ページ上部

- パンくずを [`fragments/breadcrumb-employee.html`](../../src/main/resources/templates/fragments/breadcrumb-employee.html) で表示する。
- 構成は登録モード：TOP（リンク） / 社員管理（テキスト） / 社員一覧（リンク） / 社員登録（現在位置）。編集モードは最終項目を社員編集とする。
- パンくずは `th:replace` で差し替えるため、余白用のラッパー `div` に `employee-page-header` を付与する（ホスト要素のクラスは置換で失われる）。
- 一覧（EMP001）と同様、パンくず行の下余白は `mb-3` 相当。行の高さは `employee-page-header` の `min-height` で一覧の新規登録ボタン行と揃える。

#### 入力フォーム

- 入力項目は Bootstrap の2列グリッド（`col-md-6`）を基本とする。
- 各項目はラベル左・入力右の横並びとする。ラベル幅は `form-label-fixed`（`min-width: 7rem`）で揃える。
- 備考は `col-12` で1行全幅とし、**他項目と同様にラベル左・テキストエリア右の横並び**とする。複数行のため行内の縦位置は `align-items-start` とする。
- フォーム外枠は `employee-form-card`。内側余白は `common.css` で `1rem 1.25rem` 程度とする。
- 編集時の社員番号は `readonly` の表示用 input とする。POST には含めない（`name` 属性なし）。詳細は [`emp002_post_validation_groups.md`](../07_decisions/emp002_post_validation_groups.md) §3.4 を参照。

#### 操作ボタン行

- 配置基準はフォーム外枠（カード内側）の左右余白とする（入力欄左端には揃えない）。共通方針は [`docs/02_rules/ui.md`](../02_rules/ui.md) §4.2 を参照。
- 編集モード：`d-flex justify-content-between` で左に削除（`btn-sm`）、右に一覧へ戻る・更新（`btn-form-action`）。
- 登録モード：`d-flex justify-content-end` で一覧へ戻る・登録（`btn-form-action`）を右端に配置。
- ボタン行ラッパーに `form-actions` を付与する。区切り線・上余白は直上の `border-top` ラッパーで確保する。
