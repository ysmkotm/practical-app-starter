# DEP002 部署登録・編集

**Document Version** : 1.0

**更新日** : 2026/08/05

## 1. 基本情報

|項目|内容|
|----|----|
|画面ID|DEP002|
|画面名|部署登録・編集|
|画面種類|登録・編集|
|概要|部署情報を新規登録する、または既存部署情報を編集・論理削除する画面です。登録モードと編集モードで同一テンプレートを共用します。|
|権限|未定|

---

## 2. 画面の目的

- 部署情報を新規登録する
- 部署情報を編集・更新する
- 部署を論理削除する

---

## 3. 画面イメージ

共通レイアウト（Header / Sidebar / Main）の Main 内の構成イメージです（[`docs/02_rules/ui.md`](../02_rules/ui.md) §2 参照）。

~~~text

----------------------------------------------------------------------------------------------
【入力エリア】

部署コード * [              ]    部署名 * [              ]
表示順 *     [   0          ]
----------------------------------------------------------------------------------------------

----------------------------------------------------------------------------------------------
~~~

### 編集モード

~~~text
----------------------------------------------------------------------------------------------
【ページ上部】

TOP / 部署管理 / 部署一覧 / 部署編集
----------------------------------------------------------------------------------------------
【入力エリア】

部署コード   DEP001（読み取り専用）    部署名 * [営業部        ]
表示順 *     [   1           ]

（削除は左端、主要操作は右端に配置する）
----------------------------------------------------------------------------------------------
~~~

## 6. バリデーション

|項目|内容|
|----|----|
|部署コード|必須（登録モードのみ）|
|部署コード|20文字以内|
|部署コード|先頭・末尾の空白は除去する|
|部署コード|文字種制限なし（半角英数字に限らない）|
|部署コード|一意（登録時・更新時とも、自身以外の未削除レコードと重複不可）|
|部署名|必須|
|部署名|100文字以内|
|部署名|先頭・末尾の空白は除去する|
|表示順|必須|
|表示順|0以上の整数|

### 一意性チェックと DB 制約

部署コードの一意性は、次の二層で担保する。

|レイヤー|内容|参照|
|---|---|---|
|DB 制約|部署コード（`department_code`）に UNIQUE 制約を設定済み|[`docs/04_db/table/department.md`](../04_db/table/department.md) §4|
|アプリ（本画面）|登録・更新時に、自身以外の未削除レコード（`deleted_flg = false`）と重複しないことを事前チェックする|§8.5|

DB 制約は論理削除済みレコードも含むため、アプリの事前チェックを通過しても DB 制約違反が発生しうる（EMP002 の社員番号と同じ構造）。競合時の画面表示は [`BLG-CMN-001`](../01_project/backlog.md) の方針確定後に実装する。

論理削除済みの部署コードは再利用できない（UNIQUE 制約が論理削除済み行も含むため。EMP002 §6 の方針を踏襲）。

## 8. 実装情報

### 8.1 エントリポイント

#### 登録画面表示

|項目|内容|
|----|----|
|URL|`/department/new`|
|HTTPメソッド|GET|
|テンプレート|`src/main/resources/templates/department/form.html`（新規作成）|
|Controller|`DepartmentController#showCreate`（新規作成）|

- モデルに `mode` として `"create"` を設定する。
- 空の `DepartmentForm` をモデルに設定する。

#### 編集画面表示

|項目|内容|
|----|----|
|URL|`/department/{departmentId}/edit`|
|HTTPメソッド|GET|
|テンプレート|`src/main/resources/templates/department/form.html`（新規作成）|
|Controller|`DepartmentController#showEdit`（新規作成）|

- `{departmentId}` には部署マスタ.部署ID（`department_id`）を指定する。
- モデルに `mode` として `"edit"` を設定する。
- 対象部署の情報を `DepartmentForm` に設定してモデルへ渡す。
- 対象部署が存在しない、または論理削除済みの場合の扱いは EMP002・[`BLG-EMP-004`](../01_project/backlog.md) と同様（`BLG-CMN-002` 確定まで暫定 404）とする。

#### 登録

|項目|内容|
|----|----|
|URL|`/department`|
|HTTPメソッド|POST|
|Controller|`DepartmentController#create`（新規作成）|

- `DepartmentForm` で入力値を受け取る。
- バリデーションエラー時は登録画面（登録モード）を再表示する。

#### 更新

|項目|内容|
|----|----|
|URL|`/department/{departmentId}`|
|HTTPメソッド|POST|
|Controller|`DepartmentController#update`（新規作成）|

- `{departmentId}` には部署マスタ.部署ID（`department_id`）を指定する。
- 更新対象のキーは **`@PathVariable` の `departmentId` を正** とする。hidden の `departmentId` は設けない（EMP002 と同じ方針）。
- `DepartmentForm` で入力値を受け取る。編集モードでは部署コードは画面から送信されない（`th:field` を使わず `name` 属性を付けない。`readonly` 表示のみ）。
- バリデーションエラー時は編集画面（編集モード）を再表示する。再表示時の `departmentId` は `@PathVariable` からモデルへ設定する。

#### 削除

|項目|内容|
|----|----|
|URL|`/department/{departmentId}/delete`|
|HTTPメソッド|POST|
|Controller|`DepartmentController#delete`（新規作成）|

- `{departmentId}` には部署マスタ.部署ID（`department_id`）を指定する。
- 削除対象のキーは **`@PathVariable` の `departmentId` を正** とする。hidden の `departmentId` は設けない。
- 論理削除として、部署マスタ.削除フラグ（`deleted_flg`）を `true` に更新する。
- 削除前に確認ダイアログを表示する。メッセージ形式は §8.5 を参照。

### 8.5 データ取得・更新

- 編集画面表示時は、`department_id` で部署マスタを取得する。`deleted_flg = false` のレコードのみ対象とする（既存の `findDepartmentById` を使用）。
- 登録時は `department_id` を自動採番し、`deleted_flg` は `false` を設定する。
- 更新時は `@PathVariable` の `department_id` をキーに部署マスタを更新する。部署コードは更新しない（編集モードでは読み取り専用）。`updated_at` は更新する。
- 削除時は `@PathVariable` の `department_id` をキーに `deleted_flg` を `true` に更新する。`updated_at` は更新する。
- 部署コードの一意性チェックは、登録時・更新時ともに自身以外の未削除レコードと照合する。DB 制約との関係は §6「一意性チェックと DB 制約」を参照する。
- 削除確認ダイアログのメッセージは、対象部署が分かる形式とする。例：`DEP001：営業部 を削除します。よろしいですか？`（部署コード・部署名は編集画面表示時の値を使用する）。

### 8.6 画面レイアウト（登録・編集）

[`docs/02_rules/ui.md`](../02_rules/ui.md) §4（入力画面）の適用例です。EMP002（[`EMP002_社員登録・編集.md`](EMP002_社員登録・編集.md) §8.6）と同じ構成方針を踏襲します。

|項目|内容|
|----|----|
|テンプレート|`src/main/resources/templates/department/form.html`（新規作成）|
|画面固有 JS|`src/main/resources/static/js/department/form.js`（必要な場合のみ新規作成）|
|共通 CSS|[`src/main/resources/static/css/common.css`](../../src/main/resources/static/css/common.css)（`employee-form-card` 等の入力画面共通クラスを部署管理でも再利用するか、部署専用クラスを追加するかは実装時に判断する。軽微な判断のため専用の判断記録は作らない）|

#### ページ上部

- パンくずは `breadcrumb-department.html`（DEP001 実装時に新設済み）で表示する。
- 構成は登録モード：TOP（リンク） / 部署管理（テキスト） / 部署一覧（リンク） / 部署登録（現在位置）。編集モードは最終項目を部署編集とする。

#### 入力フォーム

- 入力項目は Bootstrap の2列グリッド（`col-md-6`）を基本とする（EMP002 を踏襲）。
- 各項目はラベル左・入力右の横並びとする。
- 編集時の部署コードは `readonly` の表示用 input とする。POST には含めない（`name` 属性なし）。

#### 操作ボタン行

- 編集モード：`d-flex justify-content-between` で左に削除（`btn-sm`）、右に一覧へ戻る・更新（`btn-form-action`）。
- 登録モード：`d-flex justify-content-end` で一覧へ戻る・登録（`btn-form-action`）を右端に配置。
- EMP002 の操作ボタン行の構成（`form-actions`、配置基準）をそのまま踏襲する。

## 10. 備考

- 画面固有コンテンツは Main 領域に配置する（[`docs/02_rules/ui.md`](../02_rules/ui.md) §2.3）。
- 登録画面と編集画面は `form.html` を共用する（EMP002 と同方針）。
- 必須項目の画面上の表示方法（`*` 等）は、[`BLG-CMN-003`](../01_project/backlog.md) 確定後に [`docs/02_rules/ui.md`](../02_rules/ui.md) §4 へ反映する。
- 処理成功メッセージは Version 1.0 暫定として実装する（§7。共通方針の完全版は [`BLG-CMN-001`](../01_project/backlog.md)）。
- 排他制御（楽観的ロック等）は Version 1.0 では実装対象外とする（EMP002・[`BLG-EMP-010`](../01_project/backlog.md) と同方針）。
- 部署マスタは他マスタを参照しない（プルダウン等の外部参照がない）ため、EMP002 にあった「論理削除済みマスタの現在値補完」（[`emp002_soft_deleted_master_reference.md`](../07_decisions/emp002_soft_deleted_master_reference.md)）に相当する仕様は本画面には存在しない。
- 入力項目のレイアウト（2列グリッド・ラベル左入力右等）は §8.6 を参照する。
