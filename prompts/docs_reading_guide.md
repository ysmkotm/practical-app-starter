# 開発ドキュメントの読み方ガイド

## 使い方

`docs/` の量が多く、初見でどこから読めばよいか整理したいときに使います。下の依頼文をコピーしてください。

---

## 依頼文

```text
このリポジトリの開発ドキュメント（docs/）について、初見向けの読み方を案内してください。

次を含めてください。

1. docs 全体の役割（ソースと一体の正本であること）
2. 初めて読む場合の推奨順（docs/README.md の案内を踏まえる）
3. 「今は読まなくてよい／後回しでよい」もの
4. 目的別の最短ルート（例：動かす、機能を理解する、AI と進める、改修する）

一覧の丸写しは不要です。迷いを減らす案内にしてください。
根拠はリポジトリ内の文書にしてください。
```

---

## 補足（依頼時に足すとよい情報）

- いま知りたい目的（起動／機能理解／ルール／AI 協調など）
- すでに読んだ docs があればその旨
